# Contributing

Thanks for wanting to improve this standard. This repository is the **source of truth** of an
engineering standard shipped two ways: a Claude Code plugin, and a portable core
(`AGENTS.md` + `memory/constitution.md`) for Cursor/Gemini/Codex. See
`docs/multi-llm-distribution.md`.

## Layout

- `memory/constitution.md` — source of truth for the principles (P1–P8) and working modes.
- `memory/design-constitution.md` — the UX/UI counterpart.
- `AGENTS.md` — the portable core any LLM can read.
- `skills/*/SKILL.md` (+ `references/`) — the 25 skills. Playbook index: **`PLAYBOOKS.md`**
  (auto-generated by `scripts/gen-playbooks-index.py`, checked in CI with `--check` — **never edit
  it by hand**; run the script after adding or renaming a playbook).
- `config/team-config.example.md` — the template. The real `config/team-config.md` is git-ignored.
- `hooks/`, `.mcp.json` — enforcement and tool connections.

## The one rule that makes this reusable

**Ship the shape, never the values.** Anything specific to one team — an org name, a tenant URL, a
field id, a service inventory, a build command — belongs in `config/team-config.md` (git-ignored)
or in a `<FILL: ...>` placeholder, discovered at install time by `setup`/`onboard`.

`scripts/check-leaks.sh` enforces this in CI. If it fails your PR, the fix is not to weaken the
check — it is to move the value out of the standard.

The second-order version of the same rule: when removing a specific value would leave a sentence
empty, replace the sentence with the **method** ("how to find this in your project"), not with a
bare placeholder. A standard made of blanks teaches nothing.

## Proposing a change

1. Open an issue first (this project follows its own flow — see `AGENTS.md`).
2. Branch, then PR. A change to a principle or to the architecture needs an **ADR**
   (`skills/spec-flow/references/templates/adr-template.md`).
3. Edit the **source** (`memory/constitution.md`) — never only a copy.
4. Run the validation and update `CHANGELOG.md`:

```bash
sh scripts/validate-plugin.sh
```

5. Peer review before merge (the standard applies to itself: P3).
6. Commits follow Conventional Commits and are **not signed by an AI** (P3).

## Invariants the validation enforces

- Manifests are valid JSON, and `plugin.json`/`marketplace.json` versions agree.
- Every `SKILL.md` has valid frontmatter, and `name` matches its folder.
- Every reference cited by a skill exists, and no reference file is orphaned (uncited).
- `skills/constitution/references/constitution.md` mirrors `memory/constitution.md` exactly.
- `PLAYBOOKS.md` is up to date.
- The hooks' own tests pass (`flow-gate.test.sh`, `no-ai-signature.test.sh`).
- Nothing team-specific leaked in (`check-leaks.sh`).

## Testing a hook change

`hooks/flow-gate.sh` is the only component with mandatory tests — it can block real work, so a hole
or a false block is a production bug:

```bash
sh hooks/flow-gate.test.sh
```

Add a case for every gate you touch. A gate without a test does not merge.
