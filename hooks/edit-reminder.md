[Standard — BEFORE editing code] Does this change come from a **GitHub issue** and has it gone through **spec-flow**? Rule: every change has an issue (if there is none, ask or create it via `issues` — do not scan the backlog guessing) and goes through the spec-driven pipeline (specify→clarify→plan→tasks, which **generates `specs/<feature>/`**) — never jump from "I read the issue" to code. [When finishing] Definition of Done: tests for new code (happy path + errors) · lint/format/types green · no secrets or sensitive data · observability where needed · follow the app conventions. Security/quality (`quality`): if it touches auth, data or external input, apply OWASP; static analysis quality gate green on new code; personal data → `privacy`. FRONT/UI: use the project design system — new code is born in it, with no raw HTML/CSS or hardcoded values; legacy migrates incrementally (it does not block deploy — `design-system`) + Nielsen + WCAG. Before opening a PR: run `preflight` (exhaustive check + real tools + independent anti-hallucination verification, looping until ZERO automated findings). Full DoD in `constitution`.
